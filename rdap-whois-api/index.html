你想查询WHOIS？这是我的RDAP方案

2026-08-31T15:02:45.000Z2.1k

既然你点击了这篇文章，肯定是对标题内容感兴趣的吧！
让我给你介绍一下，我是怎么搭建RDAP以及为什么搭建。

事情起因是我在给AI发布查询域名有效期以及域名信息的时候，总感觉差点意思，我就在想要不要自己搭建一个whois查询API呢？
我就开始寻找一些支持无服务器部署的项目，因为服务器的成本是一笔不小的支出，所以才寻找相关项目绝对不是因为没钱，嘿嘿,后面经过在github一顿翻找，找到了jakejarvis的rdapper项目，该项目支持RDAP与whios双支持，但是无服务器部署不支持whois，所以只要支持RDAP查询的域名都能查询，除了一些小众域名与一些国家级域名(CCLTD)不支持外都可以！RDAP现支持**1000+**域名后缀，不支持后缀示例如下：.de（德国）、.cn（中国）、.us（美国）、.jp（日本）、.it（意大利）、.es（西班牙）、.mx（墨西哥），可以期待一下，后续应该支持的。

讲了这么多是时候解释我的API地址啦，API介绍页是https://whoiscx.delishahk.com,该介绍页支持输入域名与URL查询，高级玩家可以试试API调用，我来介绍一下API格式https://whoiscx.delishahk.com/api/?whois=查询的域名或URL，返回的数据如下：

顶层字段（非数组）

  • ok（布尔值）：表示本次 WHOIS 查询是否成功，true 表示成功。
  • queriedDomain（字符串）：用户实际查询的域名，即 delishahk.com（不区分大小写）。
  • resolvedMainDomain（字符串）：经过规范化后解析出的主域名，通常与查询域名一致。
  • links（对象）：包含与本次查询相关的链接。
    • self：当前查询 API 的完整 URL。
    • rdap（数组）：该域名可用的 RDAP（注册数据访问协议）服务端点列表，用于获取更标准的注册信息。
  • meta（对象）：元数据，包含作者信息和时间戳。
    • author：数据提供者/作者标识。
    • timestamp：查询结果生成的时间（UTC，ISO 8601 格式）。

record 对象（核心域名注册信息）

该对象包含域名 DELISHAHK.COM 的详细注册数据，其中包含多个数组字段。

1. 基础字段（非数组）

  • domain：域名的大写形式。
  • tld：顶级域（Top-Level Domain），这里是 com。
  • isRegistered：布尔值，表示域名是否已被注册（true）。
  • isIDN：是否为国际化域名（IDN），false 表示只含 ASCII 字符。
  • punycodeName：Punycode 编码后的域名（若为 IDN 则显示编码形式，此处无变化）。
  • registrar（对象）：当前注册商信息。
    • name：注册商名称（NameSilo, LLC）。
    • ianaId：IANA 分配的注册商 ID（1479）。
  • creationDate：域名注册创建时间（UTC）。
  • updatedDate：最近一次更新记录的时间（UTC）。
  • expirationDate：域名到期时间（UTC）。
  • transferLock：是否开启转移锁（true 表示禁止未经授权的转移）。
  • dnssec（对象）：DNSSEC 配置信息。
    • enabled：是否启用 DNSSEC（true）。
    • dsRecords（数组）：DS（委托签署者）记录列表，用于验证 DNS 签名链。详见下文。
  • whoisServer：传统的 WHOIS 服务器地址。
  • rdapServers（数组）：该域名支持的 RDAP 服务器 URL 列表。
  • source：数据来源（此处为 rdap，表示从 RDAP 协议获取）。
  • privacyEnabled：是否启用隐私保护（true，隐藏所有者真实信息）。

2. 数组字段详解

(1) statuses（数组）

  • 含义：域名当前的状态码（由注册局或注册商设置），影响域名的操作权限。
  • 内部元素：每个元素是一个对象，包含：
    • status：状态简称（如 client transfer prohibited）。
    • raw：原始状态字符串，通常与 status 相同。
  • 具体数据：client transfer prohibited 表示注册商禁止转移，即域名处于锁定状态，无法转出到其他注册商（通常需解锁后才能转移）。

(2) nameservers（数组）

  • 含义：该域名当前使用的权威 DNS 服务器列表。
  • 内部元素：每个元素是一个对象，包含一个字段：
    • host：DNS 服务器的主机名。
  • 具体数据：
    • diva.ns.cloudflare.com
    • sean.ns.cloudflare.com
      表示使用 Cloudflare 提供的 DNS 服务。

(3) contacts（数组）

  • 含义：域名的联系信息列表。通常包含注册人、管理员、技术联系人等，但本例仅返回了注册人（registrant）。
  • 内部元素：每个元素是一个对象，包含联系人的详细字段：
    • type：联系人类型（registrant 表示注册人）。
    • name：联系人姓名（由于隐私保护，显示为匿名化名称 Privacy User #7616123f）。
    • organization：所属组织（See PrivacyGuardian.org，说明由隐私代理服务提供）。
    • email：联系邮箱（隐私保护邮箱，格式为 pwp-...@privacyguardian.org）。
    • phone：电话号码（格式 tel:+1.3478717726，美国号码，也受隐私保护）。
    • street（数组）：街道地址行（这里是 ["1928 E. Highland Ave. Ste F104"]，一条地址）。
    • city：城市（Phoenix）。
    • state：州/省（AZ，亚利桑那州）。
    • postalCode：邮政编码（85016）。
    • country：国家（此处为空字符串，但通常应为 US，可能因隐私隐藏）。
  • 注意：因为 privacyEnabled 为 true，这些信息均为代理信息，并非真实所有者。

(4) dnssec.dsRecords（数组，位于 dnssec 对象内）

  • 含义：DNSSEC 的 DS 记录列表，用于构建信任链，验证域名 DNS 响应的真实性。
  • 内部元素：每个元素是一个对象，包含：
    • keyTag：密钥标签（一个 16 位整数，用于标识密钥）。
    • algorithm：加密算法编号（13 表示 ECDSA P-256 SHA-256）。
    • digestType：摘要类型编号（2 表示 SHA-256）。
    • digest：摘要值（十六进制字符串），用于与父区域中的 DS 记录匹配。
  • 具体数据：存在一条 DS 记录，表明该域名的 DNSSEC 已配置。

(5) rdapServers（数组，位于 record 下）

  • 含义：提供该域名 RDAP 服务的服务器 URL 列表，可用于获取更标准化的注册数据。
  • 内部元素：字符串形式的 URL。
  • 具体数据：
    • https://rdap.verisign.com/com/v1/（Verisign 为 .com 顶级域提供的 RDAP 服务）
    • https://rdap.namesilo.com/domain/DELISHAHK.COM（注册商 NameSilo 的 RDAP 服务）

(6) links.rdap（数组，位于顶层 links 对象内）

  • 含义：与 rdapServers 内容相同，但位于 links 字段中，用于提供 RESTful 风格的链接。
  • 内部元素：同样的两个 URL 字符串。

总结数组分布

数组字段路径 包含元素类型 含义
record.statuses 对象（含 status/raw） 域名状态标志
record.nameservers 对象（含 host） DNS 服务器名称
record.contacts 对象（含联系人信息） 注册人联系详情（隐私保护）
record.dnssec.dsRecords 对象（含密钥/摘要） DNSSEC 委托签署者记录
record.rdapServers 字符串（URL） RDAP 服务端点
links.rdap 字符串（URL） 同上的 RDAP 链接

附加说明

  • 隐私保护：所有联系人信息均被替换为 PrivacyGuardian.org 的代理数据，这是 NameSilo 提供的默认隐私服务。
  • 时间格式：所有日期时间为 UTC 下的 ISO 8601 格式（如 2026-01-21T13:18:25Z）。
  • DNSSEC：存在 DS 记录表示该域名已在父级（.com 顶级域）中发布了信任锚，可验证 DNS 回答的完整性。
